# bridge

The `bridge` package is the boundary layer between the Go KeePass backend and
the Qt/QML frontend. It is small by design — its only job is to let QML call Go
functions and receive change notifications.

## Why this exists

[miqt](https://github.com/mappu/miqt) lets Go code consume Qt types but cannot
*create* new `QObject` subclasses. QML requires a proper `QObject` with
`Q_PROPERTY` and `Q_INVOKABLE` annotations, which can only be expressed in C++
headers processed by Qt's meta-object compiler (`moc`). A thin C++ class is
therefore unavoidable.

The goal is to keep all real logic — file I/O, entry parsing, group traversal —
inside `internal/keepass` in Go, and limit the C++ to a dumb dispatch layer.

## How it works

### Data flow

```
QML
 │  calls Q_INVOKABLE method
 ▼
DatabaseManager  (C++, databasemanager.cpp)
 │  calls cgo-exported C function
 ▼
export.go        (Go, //export directives)
 │  calls
 ▼
keepass.Manager  (Go, internal/keepass)
 │  reads / writes
 ▼
.kdbx file
```

After any mutating operation the C++ side calls `refreshFromGo()`, which pulls
the current entry list, group list, and error string back from Go and emits Qt
signals. QML property bindings react automatically.

### Files

| File | Language | Role |
|---|---|---|
| `export.go` | Go | Exports plain C functions via `//export`; holds the singleton `keepass.Manager` |
| `databasemanager.h` | C++ | Declares the `QObject` subclass with properties and invokable methods |
| `databasemanager.cpp` | C++ | Implements each method by calling the Go exports; owns the `refreshFromGo` sync loop |
| `moc_databasemanager.cpp` | C++ (generated) | Qt meta-object glue — produced by `moc`, gitignored, regenerated by `make build` |

### Memory ownership

Go's `C.CString` allocates with `malloc`. Every `go*` function that returns a
`char *` transfers ownership to the caller. The C++ helpers `parseEntriesJson`
and `parseGroupsJson` call `goFreeString` immediately after parsing so no
string outlives its parse call.

```
Go: C.CString(s)  →  caller owns  →  C++: goFreeString(ptr)
```

### The mutex

All Go exports acquire `mu` before touching the manager. Qt's event loop is
single-threaded so the lock is never contended in practice, but it makes the
boundary explicit and safe against any future background work.

## Adding a new operation

1. Add a method to `keepass.Manager` (`internal/keepass/`).
2. Export a C wrapper in `export.go` with an `//export goXxx` directive.
3. Declare the C prototype in the `extern "C"` block at the top of
   `databasemanager.cpp`.
4. Add a `Q_INVOKABLE` declaration to `databasemanager.h` and implement it in
   `databasemanager.cpp`, calling the Go export and then `refreshFromGo()` if
   state changed.
5. Run `make build` — `moc` re-generates `moc_databasemanager.cpp` automatically.
